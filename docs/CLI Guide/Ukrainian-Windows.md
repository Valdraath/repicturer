# Посібник з командного рядка RePicturer (Windows)

`repicturer-cli.exe` — це конвертер, який працює за вікном RePicturer. Його можна запускати й самостійно, у скрипті чи
пакетному файлі, щоб обробляти зображення, не відкриваючи програму. Він уміє все, що вміє вікно: моделі ШІ,
«Масштаб - без ШІ», усі пункти параметрів, теки та списки файлів. Цей посібник для **Windows**; посібник для Linux —
[Ukrainian-Linux.md](Ukrainian-Linux.md).

## 1. Початок роботи

1. Відкрийте теку RePicturer (ту, де лежать `RePicturer.exe` і `repicturer-cli.exe`).
2. Клацніть адресний рядок Провідника, введіть `cmd` або `powershell` і натисніть Enter. У цій теці відкриється вікно
   командного рядка.
3. Виконайте першу обробку:

   ```
   repicturer-cli.exe -i photo.jpg -o photo-2x.png
   ```

   У **PowerShell** перед назвою треба додати `.\`:

   ```
   .\repicturer-cli.exe -i photo.jpg -o photo-2x.png
   ```

4. Перегляньте всі параметри:

   ```
   repicturer-cli.exe -h
   ```

Без інших параметрів використовується режим **Знешумити, збільшити - ШІ**, 2x, рівень знешумлення 0, модель `models-cunet`,
на першому GPU.

**Шляхи з пробілами** треба брати в лапки: `-i "C:\My Pictures\cat.png"`. Модель можна вказати лише назвою теки
(`-m models-realcugan-se`): вона знайдеться поруч із `repicturer-cli.exe`, хай у якій теці буде командний рядок.

## 2. Чотири режими

| Режим у вікні | Значення `-M` | Що робить |
|---|---|---|
| Знешумити, збільшити - ШІ | `denoise-scale` | прибирає шум / артефакти JPEG і збільшує за допомогою моделі ШІ |
| Збільшити - ШІ | `scale` | збільшує за допомогою моделі ШІ, без знешумлення |
| Знешумити - ШІ | `denoise` | прибирає шум, розмір не змінюється |
| Масштаб - без ШІ | `non-ai-scale` | змінює розмір класичним фільтром (Lanczos, Bicubic, Jinc...), без моделі |

Без `-M` режим визначається іншими параметрами, як у waifu2x-ncnn-vulkan: `-n -1` — лише збільшення, `-s 1` — лише
знешумлення, усе інше — знешумлення і збільшення.

## 3. Приклади

**Аніме-зображення, 2x, Real-CUGAN SE з легким знешумленням:**

```
repicturer-cli.exe -i art.png -o art-2x.png -m models-realcugan-se -n 1 -s 2
```

**Фото шириною рівно 3840 пікселів (висота за пропорціями), NMKD Superscale:**

```
repicturer-cli.exe -i photo.jpg -o photo-4k.png -M scale -m models-nmkd-superscale -W 3840
```

**Рівно 1920 x 1080 (розтягується до цього розміру, як у waifu2x-caffe):**

```
repicturer-cli.exe -i shot.png -o shot-1080p.png -M scale -m models-realesr-animevideov3 -W 1920 -H 1080
```

**Лише прибрати артефакти JPEG, розмір не змінювати:**

```
repicturer-cli.exe -i scan.jpg -o scan-clean.png -M denoise -n 2 -m models-cunet
```

**ШІ 2,25x з різкішим зменшенням після обробки (Lanczos 4 відводи з антирингом):**

```
repicturer-cli.exe -i art.png -o art.png -M scale -m models-realcugan-se -s 2.25 -F lanczos -T 4 -a relaxed
```

**Піксель-арт, 4x, без ШІ (чіткі пікселі):**

```
repicturer-cli.exe -i sprite.png -o sprite-4x.png -M non-ai-scale -F nearest -s 4
```

**Фото, 1,5x без ШІ, Lanczos 3 відводи з антирингом:**

```
repicturer-cli.exe -i photo.jpg -o photo-15.png -M non-ai-scale -F lanczos -T 3 -a relaxed -s 1.5
```

**Зменшити зображення вдвічі в лінійному світлі:**

```
repicturer-cli.exe -i big.png -o small.png -M non-ai-scale -F catrom -s 0.5 --linear-light
```

**Ігровий фон із бандингом (небо сходинками), ШІ 2x, усунення бандингу перед ШІ:**

```
repicturer-cli.exe -i sky.png -o sky-2x.png -m models-realcugan-se -s 2 --deband medium
```

**Зменшити фото з плавними градієнтами: лінійне світло й дизеринг дифузією помилки:**

```
repicturer-cli.exe -i photo.png -o photo-small.png -M non-ai-scale -F catrom -s 0.5 --linear-light --dither error-diffusion
```

**Уся тека, разом із вкладеними, у WebP, пропускаючи вже оброблені зображення:**

```
repicturer-cli.exe -i D:\Pictures -o D:\Pictures-2x -r -k -f webp -q 90 -m models-realcugan-se -s 2
```

**На CPU (без GPU), 8 ядер:**

```
repicturer-cli.exe -i art.png -o art-2x.png -g -1 -j 1:8:2
```

## 4. Усі параметри

### Вхід і вихід (усі режими)

| Параметр | Значення |
|---|---|
| `-i`, `--input path` | вхідне зображення або тека |
| `-o`, `--output path` | вихідне зображення або тека |
| `-r`, `--recursive` | обробляти й вкладені теки, зберігаючи їхню структуру |
| `-l`, `--extensions list` | розширення, які читаються з теки, наприклад `png:jpg:jpeg:webp` (типово: усі файли в ній; вкажіть, якщо в теці є й інші файли) |
| `-L`, `--file-list file` | текстовий файл UTF-8, у кожному рядку пара `вхід<TAB>вихід` (див. розділ 6) |
| `-k`, `--no-overwrite` | пропускати зображення, для яких вихідний файл уже є (він зберігається); пункт вікна *Не перезаписувати наявні файли* |
| `-f`, `--format fmt` | `png` `jpg` `webp` `bmp` `jp2` `sr` `tif` `hdr` `exr` `ppm` `tga` `gif` (типово: розширення вихідного файлу, інакше png). Анімовані GIF / WebP лишаються анімованими |
| `-q`, `--quality q` | jpg 0-100 (типово 100), webp 1-100 або 101 = без втрат (типово 101), tga 0 / 1 = RLE вимк. / увімк. |

### Режим і розмір (усі режими)

| Параметр | Значення |
|---|---|
| `-M`, `--mode mode` | `denoise-scale`, `scale`, `denoise` або `non-ai-scale` (розділ 2) |
| `-s`, `--scale r` | коефіцієнт масштабу, будь-яке додатне число: `2`, `1.5`, `0.5` (типово 2) |
| `-W`, `--width w` | вихідна ширина; висота за пропорціями, якщо не задано `-H` |
| `-H`, `--height h` | вихідна висота; ширина за пропорціями, якщо не задано `-W` |
| `-W` і `-H` разом | рівно ця ширина x висота |

### Режими з ШІ (`denoise-scale`, `scale`, `denoise`)

| Параметр | Значення |
|---|---|
| `-m`, `--model path` | тека моделі (типово `models-cunet`). Рушій визначається текою: `models-cunet`, `models-upconv_7_*`, `models-upresnet10` — waifu2x; `models-realcugan-se / -pro / -nose` — Real-CUGAN; `models-realesrgan-*`, `models-realesr-*`, `models-realesrnet-x4plus`, `models-nomos8ksc`, `models-lsdir-compact`, `models-nmkd-siax / -superscale` — Real-ESRGAN |
| `-n`, `--noise-level n` | рівень знешумлення `-1` (без нього), `0`-`3` (типово 0). Real-CUGAN: 0 = обережний. Real-ESRGAN General: сила знешумлення; LSDIR Compact: сила очищення; NMKD Siax: рівень деталей 0-3; інші моделі Real-ESRGAN очищують самі |
| `-t`, `--split-size t` | `0` = авто (типово), `1` = без поділу (усе зображення одним блоком), `2`-`512` = блоки такого розміру; для кількох GPU — по значенню на кожен (`0,0`) |
| `-c`, `--sync-gap n` | Sync gap для Real-CUGAN `0`-`3` (типово 3, 0 = вимк.) |

До ШІ параметр `--deband` може згладити бандинг оригіналу (у вікні: Параметри > Налаштування перед обробкою ШІ). Після ШІ
зображення зменшується до точного вихідного розміру (наприклад 2,25x або ширина x висота) фільтром **після обробки**:
`-F`, `-T`, `-a`, `--dither` і `--linear-light` нижче (у вікні: Параметри > Налаштування після обробки ШІ). Типово —
Bicubic Mitchell, без антирингу, без дизерингу, без лінійного світла. Рівно 2x / 3x / 4x моделі зберігається як є.

### Фільтр без ШІ, усунення бандингу й дизеринг (`non-ai-scale`, а також до / після ШІ в режимах з ШІ)

| Параметр | Значення |
|---|---|
| `-F`, `--filter name` | `nearest`, `bilinear`, `mitchell` (типово), `catrom`, `lanczos`, `spline36`, `jinc` |
| `-T`, `--taps n` | Lanczos `2` / `3` (типово) / `4` / `8`; Jinc `3` (типово) / `4` / `8`; інші фільтри його ігнорують |
| `-a`, `--anti-ringing a` | `off` (типово), `relaxed`, `strict`: зменшує ореоли `catrom`, `lanczos`, `spline36` і `jinc` |
| `--linear-light` | масштабувати в лінійному світлі; використовується лише під час зменшення (жодна сторона не росте, хоча б одна зменшується) |
| `--dither d` | `off` (типово), `ordered`, `error-diffusion`: як результат округлюється до 8-бітного кольору. Дизеринг не дає плавним градієнтам отримати нові смуги; використовується під час зміни розміру |
| `--deband d` | `off` (типово), `low`, `medium`, `high`: **Усунення бандингу** — згладжує смуги, які вже є в зображенні (небо, тіні, м'які градієнти), до ШІ або фільтра без ШІ. Змінюються лише рівні ділянки |

| Фільтр | Характер |
|---|---|
| `nearest` | Найближчий сусід: жорсткі ступінчасті пікселі, без розмиття. Піксель-арт при 2x / 3x / 4x |
| `bilinear` | швидко й м'яко, трохи розмито, без ореолів |
| `mitchell` | Bicubic Mitchell: м'яко й плавно, майже без ореолів. Надійний вибір |
| `catrom` | Bicubic Catmull-Rom: різкіше, ніж Mitchell, легкі ореоли |
| `lanczos` | різко, зберігає дрібні деталі, є ореоли (більше відводів = різкіше й більше ореолів) |
| `spline36` | між Catmull-Rom і Lanczos: різко, чисті краї, мало ореолів |
| `jinc` | круглий фільтр: різко, гладкі діагоналі, мало сходинок; досить повільний |

### Продуктивність (усі режими)

| Параметр | Значення |
|---|---|
| `-g`, `--gpu id` | GPU, який використовувати: `0`, `1`... або `-1` для CPU (типово: перший GPU). Кілька GPU: `0,1` |
| `-j`, `--threads l:p:s` | потоки читання : обробки : збереження (типово `1:2:2`). Обробка = зображення одночасно на кожному GPU (1-20) або ядра CPU при `-g -1`. Два GPU: `1:2,2:2` |
| `--vram-percent p` | використовувати не більше p % (20-80, типово 60) пам'яті GPU, вільної на початку обробки |
| `--ram-percent p` | використовувати не більше p % (20-80, типово 60) RAM, вільної на початку обробки |

### Інше

| Параметр | Значення |
|---|---|
| `-h`, `--help` | показати довідку |
| `-v`, `--verbose` | виводити кожен крок (запущені мережі, пам'ять, пристрій) |
| `--list-gpu` | показати GPU з Vulkan і вийти |
| `--progress` | машинозчитувані рядки прогресу (їх використовує вікно) |

## 5. Які параметри використовує кожен режим

| Налаштування у вікні | Режими з ШІ | Масштаб - без ШІ | Параметр |
|---|---|---|---|
| Вхідний / вихідний шлях, власні теки | ✓ | ✓ | `-i` `-o` (`-r`, `-l`, `-L`) |
| Вихідний формат / якість | ✓ | ✓ | `-f` `-q` |
| Режим | ✓ | ✓ | `-M` |
| Знешумлення / Рівень деталей | ✓ | – | `-n` |
| Збільшення: Масштаб, Ширина, Висота, Ширина x Висота | ✓ | ✓ | `-s` / `-W` / `-H` / `-W` + `-H` |
| Модель | ✓ | – | `-m` |
| Фільтр, Відводи, Антиринг (головне вікно) | – | ✓ | `-F` `-T` `-a` |
| Обчислювач | ✓ | ✓ | `-g` |
| Розмір блоку | ✓ | – | `-t` |
| Потоки | ✓ | ✓ | `-j` |
| Параметри: Sync gap для Real-CUGAN | ✓ | – | `-c` |
| Параметри: Налаштування перед обробкою ШІ (Усунення бандингу) | ✓ | – | `--deband` |
| Параметри: Налаштування після обробки ШІ | ✓ | – | `-F` `-T` `-a` `--dither` `--linear-light` |
| Параметри: Налаштування фільтрів без ШІ | – | ✓ | `--deband` `--dither` `--linear-light` |
| Параметри: Не перезаписувати наявні файли | ✓ | ✓ | `-k` |
| Параметри: межа VRAM / RAM | ✓ | ✓ | `--vram-percent` `--ram-percent` |

`-F`, `-T`, `-a`, `--dither`, `--deband` і `--linear-light` — це налаштування без ШІ в `non-ai-scale` і налаштування перед /
після обробки в режимах з ШІ: один запуск використовує один режим, тож одного набору параметрів досить.

## 6. Теки, списки файлів і пакетні файли

**Тека:** `-i` — тека, `-o` — тека для запису. Кожне зображення отримує ту саму назву з розширенням вихідного формату
(`-f`, типово png). З `-r` обробляються й вкладені теки, з тією самою структурою.

**Список файлів** (`-L`) перетворює будь-які зображення на будь-які назви. Кожен рядок — `вхід`, TAB, потім `вихід`:

```
D:\in\a.png	D:\out\a-2x.png
D:\in\b.jpg	D:\out\b-2x.webp
```

```
repicturer-cli.exe -L list.txt -m models-realcugan-se -s 2
```

**Пакетний файл** (`convert.bat`), який обробляє кожне перетягнуте на нього зображення й зберігає результат поруч:

```bat
@echo off
cd /d "%~dp0"
for %%F in (%*) do (
    repicturer-cli.exe -i "%%~F" -o "%%~dpnF-2x.png" -m models-realcugan-se -s 2
)
pause
```

Збережіть його в теці RePicturer і перетягуйте на нього зображення в Провіднику.

**PowerShell**, усі JPG з теки через «Масштаб - без ШІ»:

```powershell
Get-ChildItem D:\in -Filter *.jpg | ForEach-Object {
    .\repicturer-cli.exe -i $_.FullName -o ("D:\out\" + $_.BaseName + ".png") -M non-ai-scale -F lanczos -s 2
}
```

(Для великої кількості зображень швидше один запуск із текою: модель завантажується один раз.)

## 7. Коди завершення та повідомлення

| Код завершення (`%ERRORLEVEL%`) | Значення |
|---|---|
| `0` | усі зображення оброблено |
| `1` | частину зображень не оброблено (кожне вказано) |
| `-1` | обробка не почалася: неправильний параметр, немає моделі чи входу |

Зображення з помилкою на GPU (брак пам'яті, проблема драйвера) обробляється знову до 2 разів: спершу 2 блоками, потім 1
блоком; якщо помилка лишається, обробка зупиняється з повідомленням. У режимі «Масштаб - без ШІ» зображення, яке GPU не
зміг обробити, обробляється на CPU з тим самим результатом.

## 9. Розв'язання проблем

* **«не є внутрішньою або зовнішньою командою»**: командний рядок відкрито не в теці RePicturer. Перейдіть туди через `cd`
  або вкажіть повний шлях: `"C:\Tools\RePicturer\repicturer-cli.exe"`.
* **PowerShell пише, що команду не знайдено**: пишіть `.\repicturer-cli.exe`.
* **«no vulkan device found, falling back to cpu»**: оновіть драйвер відеокарти (NVIDIA, AMD або Intel). `--list-gpu`
  покаже GPU, які бачить конвертер.
* **«GPU error (probably out of GPU memory)»**: зменште розмір блоку (`-t 200`, `-t 100`), кількість потоків (`-j 1:1:2`)
  або збільште `--vram-percent`.
* **Незрозумілі символи у виводі**: конвертер виводить текст у UTF-8; у старій консолі спершу виконайте `chcp 65001`.
